# AniEdge for AMD — RX 9070 XT 튜닝 결과

2026-10-08, 이 PC의 AMD Radeon RX 9070 XT에서 측정했습니다. 원본 파일은 변경하지 않았습니다. 실행은 `../../start.cmd`, 기본값은 자동입니다.

## 변경 결과

저해상도는 기존 Real-CUGAN Pro conservative x2 가중치를 유지했습니다. FP16 변환과 RGB8 입출력, 전처리·후처리의 GPU 그래프 통합, 해상도 고정 최적화, DXGI의 RX 9070 XT 선택을 적용했습니다. 새 모델을 학습한 작업은 아닙니다. CPU 추론 fallback은 금지했습니다.

HD·고FPS는 ArtCNN C4F32 Vulkan 셰이더로 분리했습니다. 원본 크기에서 휘도를 내부 2배 재구성한 뒤 창 크기로 표시합니다. 입력 해상도를 작게 줄여 Real-CUGAN에 넣는 방식이 아닙니다. 1440p에서도 실제 CNN을 실행하도록 셰이더의 조건을 수정했습니다. 모든 HD 재생에서 8개 ArtCNN 패스를 확인했습니다.

## 동일 프레임 처리 속도

640×480 애니메이션 원본의 10·20·30초에서 각 20프레임, 총 60프레임을 사용했습니다. 각 모델을 순차로 실행했고 3회 워밍업 뒤 측정했습니다. 디코딩, 렌더링, 음성, 디스크 입출력과 초기 로딩은 제외했습니다.

| 경로 | 처리량 | 처리 p95 |
|---|---:|---:|
| 기존 FP32 + CPU 전처리·후처리 | 28.39fps | 36.77ms |
| FP16 + GPU 전처리·후처리 + 입력 크기 고정 | 89.11fps | 11.39ms |

약 **3.14배** 빨라졌습니다. 같은 내용을 1280×720으로 확대해 처리 용량을 확인한 경우 29.65fps / p95 34.10ms였습니다. 합성 확대 입력의 결과이며 실제 720p 복원 화질 검증은 아닙니다. 720p에서는 처리 여유가 부족하므로 자동 HQ 선택을 640×480 상당 이하·30fps 이하로 제한했습니다. HQ는 CFR 순차 재생이며 시간 탐색을 지원하지 않습니다.

## FP16 변환 오차

15개 파일의 10·30·50초, 총 45개 장면에서 기존 FP32 결과와 비교했습니다. 최대 평균 절대 오차 0.2055/255, 최저 PSNR 54.96dB, 최대 단일 채널 오차 5/255입니다. 사전 기준 MAE < 0.5, PSNR ≥ 50dB를 45개 모두 통과했습니다. HD 장면은 이 저해상도 모델 정밀도 평가에서만 축소했습니다.

이 값은 FP16 변환의 수치 유사도입니다. HR 정답 대비 복원 정확도, 시간 축 깜빡임, ArtCNN과 Real-CUGAN의 동등한 화질, NVIDIA VSR보다 우수한 화질을 입증하지 않습니다.

## 최종 재생 검증

GPU 작업을 겹치지 않고 15개 파일을 각 약 10초(평균 FPS 기준 프레임 수)씩 음성과 함께 재생했습니다. 모든 프로세스가 정상 종료했고, 13/15개에서 렌더러 드롭이 0이었습니다. 디코더 드롭은 모든 파일에서 0입니다. 파일 이름에 360/480/720이 있어도 13개는 실제 2560×1440 약 60fps입니다.

1440p·60fps의 GPU 렌더 패스 평균 합계는 10.90~10.96ms로, 60fps의 16.67ms 프레임 간격보다 짧았습니다. GPU 패스 평균은 CPU·디코딩·표시 지연을 포함한 전체 처리 p95가 아닙니다. 480p 실제 재생 중 처리량은 83.27fps, p95 13.24ms, 드롭 0입니다.

모바일 1080p는 최종 검사에서 드롭 4개, 소프트웨어 A/V 차이 최대 51.61ms가 남았습니다. 별도 240프레임 비교에서 AI 없는 원본도 기본 음성 동기화에서 4개, 화면 주사율 보정에서 2개 드롭이 발생했습니다. AI + 화면 주사율 보정에서는 4개였습니다. 모델 연산 부족만으로 설명할 수 없으며, 시작 구간과 원본 타임스탬프 처리를 더 개선할 여지가 있습니다. 1440p·60fps 13개 중 12개는 드롭 0이었고, 나머지 한 개는 약 0.43초 시점에 1개가 기록됐습니다. 모바일 1080p의 드롭 증가는 약 0.66초와 3.20초에 기록됐습니다. 드롭 발생 시점은 `playback-events.json`에 기록했습니다. 모든 드롭을 제거했다고 주장하지 않습니다.

현재 HD는 30fps 이하에 `display-resample`, 고FPS에 `audio`를 적용합니다. 앞의 비교 실험과 최종 재생 측정은 워밍업 일시정지 여부와 프레임 수가 다르므로 A/V 최대값을 직접 동등한 반복 실험으로 해석하지 마세요.

## 범위와 재현

검증한 HD 표시 창은 최대 약 2417×1360이며 실제 4K 전체화면 재생은 측정하지 않았습니다. HW 디코더는 `d3d11va-copy`여서 전체 파이프라인 무복사를 입증하지 않습니다. RDNA 행렬 가속 명령 사용이나 전체 에피소드의 장시간 안정성도 입증하지 않습니다.

`corpus.json`은 실제 입력 메타데이터, `speed.json`은 처리 측정값, `precision.json`은 45개 정밀도 결과, `playback-corpus.json`은 최종 재생 결과, `mobile-baseline.json`은 원본 비교입니다. 저장소 루트의 compare_speed.py, validate_model_precision.py, validate_playback.py로 재현할 수 있습니다. GPU 검증 도구는 동시에 실행하지 마세요. 추가로 런처 초기화·프로필 경계 조건·Python 구문·HD 래퍼 종료 시 소유 렌더러 정리를 확인했습니다.

기술 출처: [DirectML 실행 공급자](https://onnxruntime.ai/docs/execution-providers/DirectML-ExecutionProvider.html), [FP16 변환](https://onnxruntime.ai/docs/performance/model-optimizations/float16.html), [ArtCNN](https://github.com/Artoriuz/ArtCNN), [mpv 동기화 옵션](https://mpv.io/manual/master/#options-video-sync). 모델·셰이더 해시는 vendor/sources.json에 고정했습니다.
